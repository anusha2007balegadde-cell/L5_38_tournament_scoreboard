
# Lab 5 - Reflection

### 1. What is the purpose of static code analysis?

Static code analysis examines source code without executing it. It helps identify programming errors, security vulnerabilities, and coding style violations.

### 2. What did you learn from Pylint, Bandit, and Flake8?

Pylint helped improve code quality and naming conventions. Bandit identified potentially insecure coding practices. Flake8 helped correct formatting and PEP 8 style violations.

### 3. What challenges did you face?

Initially, the program had several code quality issues, a mutable default argument, insecure coding patterns, and formatting violations. These were resolved using the three static analysis tools.

### 4. How does static code analysis improve software quality?

It helps developers detect problems early, improve readability, reduce security risks, and maintain consistent coding standards.

### 5. What did you achieve in this lab?

I improved the tournament scoreboard program using Pylint, Bandit, and Flake8. I also learned how to interpret analysis reports, fix issues, verify improvements, and maintain changes using GitHub.
